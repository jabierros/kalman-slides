Maximum Likelihood Estimation (MLE) of Model Parameters

The goal of Maximum Likelihood Estimation in the context of state-space models (like the Kalman Filter) is to find the set of unknown system parameters that makes the observed sequence of logged measurements most probable.

0. The Epistemic Framework: Reality vs. Knowledge

Before formulating the Maximum Likelihood Estimation, we must rigorously define the boundary between the true physical reality of the system and our epistemic knowledge (or lack thereof) about that reality. We assume that the underlying system is governed by exact, deterministic laws; probability does not exist in the system itself, but solely in our ignorance of its true state.

The Deterministic Reality (The Unknown Truth)

We define the true state of the dynamic system and its measurements using strictly deterministic variables. There is no randomness in these nonlinear process and sensor equations:

  • : The true dynamic state. Variables representing the state of the system.
  • : The true observable magnitude. This is the exact value out in the world that a hypothetical, perfectly flawless sensor would read (e.g., the exact, true acceleration or voltage).
  • : The true process modeling error. This is the exact, deterministic gap between our idealized nonlinear process model and the true evolution of the system.
  • : The true sensor equation error. This is the exact, deterministic gap between our idealized nonlinear sensor mapping and the true physical magnitude.

The equations are exact, even if the true modeling errors remain unknown to us.

Advanced Implementation Detail: IEKS / LTV Optimization Architecture

Evaluating Jacobians dynamically inside a high-frequency numerical optimizer (especially during finite-difference gradient calculations or line searches) is computationally ruinous. It also creates a non-smooth, "chattering" energy landscape as the EKF constantly re-linearizes at every micro-step.

To solve this, advanced implementations leverage an Iterated Extended Kalman Smoother (IEKS) at each major optimization step to construct a Linear Time-Varying (LTV) approximation.

1. The IEKS Trajectory (Per Optimizer Step )

2. Linearize and Freeze

3. The Fast KF Runs (Gradients & Line Search)

To determine the next parameter step , the numerical optimizer must evaluate the NLL function multiple times (e.g., perturbing parameters slightly to calculate local gradients). For these localized runs within the optimization step, do not run an EKF. Evaluate the NLL by running a strictly linear Kalman Filter (KF) using the frozen LTV Jacobians. This makes the multiple gradient computations orders of magnitude faster and guarantees a smooth, convex local optimization landscape.

4. Update and Repeat

Once the optimizer computes the step and updates to , the localized LTV approximation is discarded. Return to Step 1 to run the IEKS with the new parameters, re-linearize to form a new LTV system, and repeat until converges entirely.
